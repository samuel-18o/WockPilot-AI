# WorkPilot AI (formerly VoiceAgent)

WorkPilot AI is a small freelancer-focused productivity assistant combining a chat interface, Supabase data integration, and an n8n webhook-based backend for tool-driven automations. This repository contains the full frontend + SSR application built with Vite, React, TypeScript and TanStack Router.

## Features
- Conversational assistant UI (chat surface)
- Session persistence and conversations list
- Dashboard metrics powered by Supabase (projects, time logs)
- Tool integration via n8n webhook (extensible automation)
- Server-side rendering support and simple deploy-ready build

## Tech stack
- React + TypeScript
- Vite (build & dev)
- TanStack Router (routing)
- Supabase (database)
- n8n (webhook automation)
- Framer Motion, lucide-react for small UI flourishes

## Architecture overview
The app is intentionally small and feature-focused. Key folders:

- `src/components/` — UI components (feature-first layout). The chat UI lives in `src/components/chat/Chat.tsx`.
- `src/services/` — backend-facing service modules (e.g., `services/dashboard.ts`).
- `src/integrations/` — third-party clients (e.g., `integrations/supabase.ts`).
- `src/routes/`, `src/router.tsx`, and `src/routeTree.gen.ts` — router and route definitions (TanStack Router generated tree is preserved).
- `src/client.tsx`, `src/server.ts`, `src/start.ts` — application bootstrap, preserved to avoid breaking SSR/routing.

## Supabase integration
Supabase is used as the primary data store for projects and time logs. The client is configured in `src/integrations/supabase.ts` and exported as `supabase`. The service layer in `src/services/dashboard.ts` exposes functions such as `fetchProjects()` and `fetchTimeLogs()` used by hooks and components.

Important: Do not change Supabase table names without updating the queries in `services/dashboard.ts`.

## n8n webhook integration
The chat surface posts messages to an n8n webhook defined by the environment variable `VITE_N8N_WEBHOOK_URL`. The webhook should return JSON with at least a `reply` string. Optionally include `toolUsed` and `sessionId` fields.

Example minimal response from n8n:
```
{ "reply": "Here is the answer...", "toolUsed": null }
```

## Environment variables
Create a `.env` file at the project root (see `.env.example`) with the following keys:

- `VITE_N8N_WEBHOOK_URL` — full URL to the n8n webhook endpoint.
- `VITE_SUPABASE_URL` — Supabase project URL.
- `VITE_SUPABASE_ANON_KEY` — Supabase anon/public key.

Example `.env` (do not commit):
```
VITE_N8N_WEBHOOK_URL=https://example.com/webhook
VITE_SUPABASE_URL=https://abcd.supabase.co
VITE_SUPABASE_ANON_KEY=public-anon-key
```

## Development — quick
Install dependencies and run dev server:

```bash
npm install
npm run dev
```

The app runs at http://localhost:8080/ by default.

## Available scripts
- `npm run dev` — Start Vite dev server (local SSR dev supported)
- `npm run build` — Build client + SSR artifacts
- `npm run lint` — Run ESLint

## Build & deploy
1. `npm run build` — produces `dist/client` and `dist/server` artifacts.
2. Deploy according to your chosen platform (Cloudflare Workers, Node server, etc.). The `wrangler.jsonc` and `dist/server/wrangler.json` provide a starting point for Cloudflare Workers deployments.
